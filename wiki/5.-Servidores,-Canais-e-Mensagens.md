# 💬 5. Servidores, Canais e Mensagens

No ecossistema do Concord, servidores e canais não são registros mantidos em uma empresa de hospedagem. Eles são **grafos criptográficos de permissões e dados** criados pelos próprios usuários.

---

## 🏰 Como Funcionam os Servidores

Quando você clica em criar um servidor no Concord:
1. Uma chave simétrica aleatória de 32 bytes (`serverKey`) é gerada na sua máquina.
2. Um ID único é calculado de forma autocertificada:
   $$\text{serverId} = \text{SHA-256}(\text{SuaChavePública} + \text{nonce})$$
3. Uma operação assinada do tipo `server.create` é registrada no seu log local, definindo você como o **Proprietário Inalienável (Owner)** daquele servidor.
4. O Concord começa a anunciar na DHT do Hyperswarm o tópico público derivado dessa chave.

---

## 🎟️ Códigos de Convite Criptografados

Para convidar amigos para o seu servidor, clique no menu do servidor e selecione **"Criar Convite"**:

### O que existe dentro do Código de Convite?
Um código de convite do Concord é uma string segura que codifica:
- O **ID do servidor**
- A **chave simétrica de 256 bits** necessária para decifrar as mensagens daquele servidor
- O **endereço de tópico da DHT** onde os membros se encontram

> [!SECURITY]
> Qualquer pessoa com o código de convite pode se conectar e decifrar as mensagens do servidor. Por outro lado, qualquer pessoa na internet que tente escanear a DHT encontrará apenas dados aleatórios indistinguíveis de ruído criptográfico, já que não possui a chave contida no convite.

### Como Entrar em um Servidor
1. Clique no botão `+` na barra de servidores à esquerda.
2. Selecione a aba **"Entrar com Convite"**.
3. Cole o código fornecido pelo seu amigo e clique em entrar.
4. Seu aplicativo se conectará aos nós do servidor e iniciará a sincronização automática de todo o histórico de canais e mensagens!

## 📁 Canais de Texto e Canais de Voz

Dentro de cada servidor, os administradores podem criar dois tipos de canais:

1. **Canais de Texto**:
   - Para envio de mensagens assíncronas persistidas no log do SQLite.
   - Histórico permanente com sincronização entre peers.
2. **Canais de Voz**:
   - Ambientes em tempo real para conversas por voz, vídeo de webcam e transmissão de tela.
   - Quando você clica em um canal de voz, você entra automaticamente na conferência WebRTC daquele grupo.

## 💬 Recursos de Mensagens e Chat

A interface de chat do Concord foi projetada para ser ágil e completa:

- **Respostas e Citações (`reply_to`)**: Clique no ícone de resposta em qualquer mensagem para iniciar uma citação encadeada. A interface destaca a mensagem original e permite aos membros acompanhar discussões paralelas com clareza.
- **Edição e Exclusão**: Apenas o autor original pode editar sua própria mensagem (`message.edit`). Moderadores com cargo apropriado podem registrar operações de exclusão.
- **Sanitização Rigorosa de Links**: O componente `MessageText.tsx` analisa URLs e renderiza apenas protocolos seguros (`http://` e `https://`). Esquemas perigosos como `javascript:`, `data:` ou `file:` são desarmados automaticamente contra ataques de phishing ou XSS.
- **Rate Limit de Proteção no Chat**: Para evitar que scripts maliciosos inundem canais de texto com spam, o cliente e o servidor aplicam um limite padrão de **5 mensagens a cada 3 segundos** por canal.

## 🛡️ Sistema de Cargos e Permissões por Bitmask

O gerenciamento de moderação do Concord (`packages/core/src/roles.ts`) utiliza uma máscara de bits (Bitmask) ultraeficiente para controlar permissões:

```typescript
export const PERMISSIONS = {
  ADMINISTRATOR:   1 << 0,  // Acesso total (pode gerenciar cargos e canais)
  MANAGE_CHANNELS: 1 << 1,  // Criar e deletar canais
  MANAGE_ROLES:    1 << 2,  // Atribuir cargos a membros de nível inferior
  KICK_MEMBERS:    1 << 3,  // Parar de aceitar operações de um usuário
  MUTE_MEMBERS:    1 << 4,  // Silenciar áudio de um usuário nas chamadas
  SEND_MESSAGES:   1 << 5,  // Enviar mensagens em canais de texto
} as const;
```

### Regras Imutáveis da Moderação P2P
Diferente de sistemas centralizados vulneráveis a invasões de painel, o Reducer do Concord valida regras criptográficas que nem mesmo clientes alterados conseguem contornar:
1. **O Dono é Inviolável**: O proprietário original que assinou o `server.create` nunca pode ser expulso ou rebaixado por nenhum administrador.
2. **Sem Auto-Promoção**: Um usuário comum ou moderador não pode emitir uma operação concedendo a si mesmo permissões adicionais. O Reducer de todos os outros peers rejeitará a operação como inválida.
3. **Hierarquia de Cargos**: Um moderador não pode expulsar outro moderador com o mesmo nível de permissão ou superior.
