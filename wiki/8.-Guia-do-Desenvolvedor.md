# 🛠️ 8. Guia do Desenvolvedor e Contribuição

Este guia fornece todas as instruções necessárias para desenvolvedores que desejam configurar o ambiente local, rodar os aplicativos, executar a suíte de testes e contribuir com melhorias para o **Concord**.

---

## 🏗️ Estrutura do Monorepo

O repositório é gerenciado através de **npm workspaces** com TypeScript e arquitetura modular:

```text
Concord/
├── apps/
│   ├── desktop/     # Aplicativo Electron: processo principal, tray, IPC, fuses
│   ├── server/      # Ponte Web: servidor WebSocket + Express para o navegador
│   └── web/         # Interface gráfica: React 19, Tailwind CSS, WebRTC
├── packages/
│   ├── core/        # O núcleo: identidade Ed25519, SQLite, CRDT, Hyperswarm P2P
│   └── types/       # Definições de tipos TypeScript compartilhadas
├── wiki/            # Documentação completa da Wiki oficial
└── .github/         # Workflows de CI/CD e automação de Releases
```

---

## 💻 Pré-Requisitos de Desenvolvimento

1. **Node.js**: Versão **22.x** ou superior obrigatória.
2. **npm**: Versão 10 ou superior.
3. **Compiladores Nativos C/C++** (para compilação dos módulos `better-sqlite3` e `sodium-native`):
   - **No Windows**: Ferramentas de build do Visual Studio C++ (ou instale com `npm install -g windows-build-tools`).
   - **No Linux**: `build-essential` e `python3`.
   - **No macOS**: Xcode Command Line Tools.

## ⚡ Comandos Essenciais

### 1. Clonar e Instalar Dependências
```bash
git clone https://github.com/jotasrn/Concord.git
cd Concord
npm install
```

### 2. Rodar em Modo de Desenvolvimento (Desktop)
Inicia o processo principal do Electron com recarregamento a quente da interface:
```bash
npm run dev
```

### 3. Rodar em Modo Web (Navegador)
```bash
# Compilar pacotes base e interface
npm run build

# Iniciar o servidor web na porta 3001
npm start --workspace=apps/server
```
Abra o navegador em `http://localhost:3001`.

## 🧪 Suíte de Testes Automatizados

O Concord possui mais de **150 testes automatizados** cobrindo criptografia, convergência de CRDT, rede P2P simulada e negociação WebRTC:

```bash
# Executa todos os testes do monorepo
npm test
```

### Detalhamento por Módulo:
- **`packages/core`**: Testes com o test runner nativo do Node.js (`node --test`), cobrindo derivação de chaves, integridade de banco de dados, assinaturas de mensagens e proteção contra peers hostis.
- **`apps/web`**: Testes com Vitest para o motor de áudio, medidores de volume e negociação WebRTC P2P simulada (`fakeWebRtc.ts`).
- **`apps/server`**: Testes com WebSocket simulado para concorrência de abas, limites de chamadas por segundo e isolamento de diretórios por dispositivo.

## 🎨 Qualidade de Código e Formatação

Nosso pipeline de CI confere estilo e tipagem em todo commit:

```bash
# Verificar e corrigir formatação com Prettier
npm run format

# Apenas verificar formatação (igual ao CI)
npm run format:check

# Executar análise estática de código com ESLint
npm run lint
```

## 📦 Gerando o Instalador Localmente

Para empacotar o executável do Windows localmente (gerando o instalador `.exe` e o `.zip` portátil):

```bash
npm run dist
```
O script executa a compilação completa dos pacotes, copia os arquivos para o diretório isolado de staging (`apps/desktop/scripts/stage.js`), chama o `electron-builder` e grava os fuses de segurança no executável (`apps/desktop/scripts/afterPack.js`).

## 🤝 Como Contribuir

1. Faça um **Fork** do repositório.
2. Crie uma branch para sua funcionalidade ou correção:
   ```bash
   git checkout -b feat/minha-melhoria
   ```
3. Faça suas alterações mantendo o padrão de código existente e adicionando testes para comportamentos novos.
4. Garanta que todas as verificações passem localmente:
   ```bash
   npm run lint && npm run format:check && npm test
   ```
5. Envie um **Pull Request** detalhando as motivações da mudança!
